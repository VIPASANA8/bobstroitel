# Referral Profile UI Design

**Date:** 2026-09-08

**Status:** Approved

**Scope:** Player-facing referral summary in the existing profile

## Goal

Give every authenticated Telegram player a clear place to find and share their referral link and to understand the current state of their rewards. The screen must expose the existing referral programme without granting access to CASH-only operations.

The existing settlement rules remain unchanged:

- the referrer receives 15% for the referred player's first 30 days and 5% afterward;
- Poker and Cube are settled independently from income the project actually earned;
- rewards wait for seven days before release;
- Cube losses carry forward until later Cube profit covers them;
- released rewards are credited automatically to the player's money balance.

The partner agreement is outside this UI change. Its production setting remains 50% of monthly Cube net profit, with Poker excluded.

## Product Decisions

### Audience

The referral tab is available to every authenticated user, regardless of CASH mode or CASH allowlist membership. Authentication remains required. Opening this endpoint must not expose the wallet, deposits, withdrawals, CASH tables, or any other gated operation.

### Placement

Add a dedicated `Рефералы` tab to the existing profile mode navigation. It sits beside the profile and cashier tabs and remains visible in both Poker and Cube contexts. If the cashier is hidden for a user, the navigation still contains the profile and referral tabs.

A dedicated tab was chosen over a cashier card or modal because referral income spans both Poker and Cube and should remain discoverable outside the cashier.

### Content and hierarchy

The tab contains one focused referral panel:

1. A heading and short programme explanation: `15% первые 30 дней, затем 5%` from actual project income generated by invited players in Poker and Cube.
2. A read-only personal Telegram link with a primary `Поделиться` action and a secondary `Копировать` action.
3. Three summary values:
   - `Приглашено` from `invited`;
   - `На проверке` from `pending_micros`;
   - `Выплачено` from `paid_micros`.
4. A brief note that rewards wait for seven days and are credited automatically after release.
5. A Cube carryover notice rendered only when `carryover_micros` is negative. It states how much the Cube referral group must earn back before the next Cube reward. It must not imply that Poker income is affected.

All money values are displayed in USDT with the shared cash formatting convention. The UI does not add a claim or withdrawal action because release is automatic.

## API and authorization

Keep the existing route and response shape:

`GET /api/cash/referral`

Change only this route's dependency from `get_cash_user` to `get_current_user`. The route still resolves the authenticated user's referral summary and tenant-specific Telegram bot link. All other `/api/cash/*` routes retain the CASH access gate.

The response fields remain:

- `code`
- `start_payload`
- `link`
- `invited`
- `pending_micros`
- `paid_micros`
- `carryover_micros`

Generating a code on the first request is expected and remains idempotent. No settlement, ledger, schema, admin, or partner-share changes are required.

## Client behaviour

The profile boot sequence authenticates first, then loads the referral summary independently of CASH wallet loading. A CASH access failure must not hide or disable the referral tab.

The referral request is lazy: it runs when the referral tab is opened for the first time and its successful result is retained for the life of the page. This avoids adding a blocking request to the normal profile load while keeping the first visit responsive with a small loading state.

Sharing behaviour follows this order:

1. Inside Telegram Mini App, open Telegram's share URL using the available Telegram WebApp navigation API.
2. Outside Telegram, use the Web Share API when available.
3. If sharing is unavailable or cancelled, leave the screen unchanged; copying remains available.

The copy action uses the Clipboard API and reports success next to the actions without replacing the button label permanently. If `link` is absent, the UI presents the referral code and allows it to be copied; the share action is disabled with an explanatory label.

## States and error handling

- **Loading:** compact skeletons occupy the link and three summary values; actions are disabled.
- **Success:** render server values and enable the appropriate actions.
- **No referrals:** show zero values without a separate empty-state illustration; the link remains the primary next action.
- **Negative Cube carryover:** show the conditional Cube notice using neutral explanatory styling rather than an alarm treatment.
- **Authentication failure:** reuse the profile's existing Telegram sign-in handling.
- **Network or server failure:** keep the tab visible, show an inline message and a `Повторить` button, and do not affect other profile panels.
- **Copy/share failure:** announce a concise status through an `aria-live` region and keep both actions usable where supported.

## Accessibility and responsive layout

The new tab follows the existing ARIA tab pattern and keyboard controls. The referral panel uses a logical heading order, real buttons, a labelled read-only link field, visible focus states, and an `aria-live="polite"` status region.

On narrow screens the three summary values remain in a compact three-column row while the two actions stack if their labels no longer fit. Long Telegram links truncate visually but remain fully available to copy. The implementation reuses current profile colour, spacing, radius, typography, and reduced-motion conventions rather than creating a second visual system.

## Verification

Backend tests must prove:

- an authenticated user outside the CASH allowlist can fetch the referral summary;
- the same route works when CASH mode is off;
- an unauthenticated request receives 401;
- other CASH endpoints remain gated.

Client and structural tests must prove:

- the referral tab and panel have correct tab/tabpanel relationships;
- CASH failure does not hide the referral tab;
- returned counts and money values render correctly;
- the Cube carryover notice appears only for a negative value and uses its absolute amount;
- a missing link falls back to copying the code and disables sharing;
- copy, Telegram share, Web Share fallback, retry, and live status behaviour work;
- keyboard tab selection and mobile layout remain usable.

Run the focused referral/profile tests, the full Python suite, and the applicable browser checks before production deployment. Production verification consists of an authenticated referral request, an unauthenticated 401 check, a mobile and desktop visual smoke test, and confirmation that CASH gating remains intact.

## Out of scope

- referral leaderboards, per-invite lists, charts, source-by-source earnings history, and campaign management;
- manual claiming or withdrawal controls;
- changes to referral percentages, seven-day hold, carryover arithmetic, fraud handling, ledger entries, or settlement cadence;
- changes to partner profit sharing.
