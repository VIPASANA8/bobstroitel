# CASH table mode and access — пакет 2

**Goal:** Пометить столы серверным активом, сохранить способ входа в сессии и гарантировать, что незавершённый CASH не попадёт в PLAY runtime, к ботам или неподтверждённому live-доступу.

**Scope:** Схема, каталог, аутентификация, настройки и защитные проверки посадки. Без cash escrow, точной игровой арифметики, платежей, новых публичных денежных API и вкладок лобби.

## Task 1: Asset стола

- [x] Добавить неизменяемый `poker_tables.asset` со значениями `PLAY`/`CASH_USDT`, default `PLAY` для сохранения существующих столов.
- [x] Шесть `DEFAULT_TABLES` всегда сеять как PLAY; `TableSummary`, `list_tables` и `quick_play` учитывать asset.
- [x] Координатор по умолчанию получает только PLAY. CASH нельзя незаметно подменить PLAY-столом.
- [x] Существующие пользовательские PLAY-комнаты не конвертировать SQL-миграцией: их закрытие и возврат средств требуют отдельной процедуры.

## Task 2: Происхождение сессии и mock gate

- [x] Добавить `auth_sessions.auth_method`: `telegram`, `dev`, `guest`, `legacy`. Существующие сессии получают `legacy`, а новые сохраняют фактический способ входа.
- [x] Добавить `POKER8_CASH_MODE=off|mock`; default `off`. `mock` разрешён только в development/test, `live` в этом пакете отвергается.
- [x] Внутренняя cash dependency разрешает тестовые способы входа только в mock; legacy неизвестного происхождения отвергается. Публичных cash route пока нет.

## Task 3: CASH-off защита runtime

- [x] PLAY `SeatingService` отвергает ready и boundary для CASH до пакета точной арифметики/escrow.
- [x] CASH-столы не получают системных игроков и не обрабатываются координатором PLAY.
- [x] Новые PLAY-комнаты выключены по умолчанию; временный legacy-флаг работает только в development/test. Прямое создание CASH через старый room API невозможно.

## Task 4: Миграция и проверка

- [x] Замороженная миграция от актуального head; обновить ожидаемую ревизию.
- [x] Проверить backfill, ограничения, повтор upgrade, downgrade и metadata на PostgreSQL.
- [x] Выполнить cash tests, обычную регрессию, Alembic heads, diff check и независимое ревью.

## Не является результатом

Наличие `CASH_USDT` в таблице не включает игру. До пакета 3 отсутствуют cash-seat FK, денежный runtime и безопасный settlement. `mock` — только серверный тестовый допуск, он не включает платежи и недоступен в production.
