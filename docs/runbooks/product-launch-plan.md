# План продуктового старта: публичный PLAY + открытый CASH-пилот

Дополняет `prod-launch-checklist.md` (инфраструктура) и `cash-mock-pilot.md`
(закрытый mock-контур). Здесь — что отделяет текущий код от публичного запуска.

## Scope

- **In:** публичный PLAY; открытая регистрация в CASH; реальные пополнения и
  выводы; допуск пользователя (возраст/гео/KYC/санкции); лимиты; операторская
  панель; мониторинг; поддержка.
- **Out:** турниры, мультиботовая сеть, рефералка, мобильные приложения,
  собственное хранение приватных ключей, масштабирование до подтверждения
  пилотной экономики.

## Действия

### Этап 1. Публичный PLAY (не зависит от CASH)

1. ~~**Починить boot на боевом домене.**~~ Сделано 2026-09-03: домены тенанта
   пробрасывались верно (`43c184d`), но токен бота в `.env` был от другого бота.
   Заменён, стек передеплоен, вход проверен синтетически подписанным `initData`.
2. **Проверить путь целиком:** вход через Telegram → лобби → шесть столов →
   раздача → реконнект → выход → профиль. Плюс Quick Play и idle-боты.
3. **Изолировать PLAY от CASH.** Сбой или выключение CASH не должен ронять
   лобби и профиль: сейчас оба падают в общий fallback без разбора причины.
4. Выкат PLAY в `POKER8_ENV=production`, `POKER8_OPEN_ACCESS=0`,
   `POKER8_CASH_MODE=off`.

### Этап 2. Production-контур CASH (код)

5. **Добавить режим `production` в `online/config.py`** и снять привязку CASH к
   `POKER8_ENV=test`. Требования режима: production-адаптеры вместо mock,
   заполненные партнёрские креды, `secure`-cookie, никакого `dev`/`guest`.
6. **Реальный исполнитель выплат** вместо `MockPayoutExecutor`. Приватные ключи
   в приложении не хранить: подпись и custody — у внешнего исполнителя,
   приложение только ставит задачу и читает статус, включая `unknown`.
7. **Закрыть дыру допуска в `cash/access.py`:** денежные маршруты только для
   `auth_method == "telegram"` с проверенным `telegram_user_id`. `guest` и `dev`
   отсекать до кошелька и до CASH-стола.
8. **Допуск пользователя перед первым денежным действием:** возраст, страна,
   KYC/AML-статус, санкционные списки, заморозка аккаунта, согласие с правилами.
   Сейчас в коде нет ни одной из этих проверок.
9. **Лимиты открытого пилота.** Регистрация публичная, без allowlist, но с
   минимальными потолками: депозит, бай-ин, проигрыш за сессию, вывод; один
   активный вывод; cooling-off; самоисключение; ручная проверка крупных и
   подозрительных операций. Расширить `cash/antifraud.py`.

### Этап 3. Партнёры и деньги

10. **CASE8 P2P:** получить боевой URL, токен и сертификат; в sandbox
    подтвердить открытые вопросы из `docs/case8-p2p-partner-contract.md` —
    включает ли `Amount` комиссию, и формат копеек. До подтверждения — mock.
11. **Доказать сохранность денег на PostgreSQL:** атомарность
    deposit/buy-in/settlement/withdrawal, конкурентные запросы, повтор
    события партнёра, выход во время раздачи, рестарт, восстановление из
    бэкапа, неизвестный исход выплаты, ежедневная независимая сверка
    (`cash/reconciliation.py`, `cash/fiat_reconciliation.py`,
    `tools/cash_backup_restore_check.py`). Расхождение останавливает только
    затронутый стол и сохраняет резерв.

### Этап 4. Безопасность и операции

12. Threat model и независимый security review денежного контура.
13. Ротация секретов, rate limits, антифрод, аудит действий операторов,
    алерты, бэкапы вне сервера.
14. Круглосуточный kill switch `POKER8_CASH_MODE=off`, не останавливающий PLAY.

## Release gates

**Gate PLAY**
```
python -m pytest -q
python -m pytest -m postgres -q
python -m pytest tests/e2e -m e2e -q
node --check static/app.js
```
плюс миграционный прогон и нагрузочный тест (100 соединений / 20 столов).

**Gate CASH** — всё вышеперечисленное, плюс:
- sandbox-сценарии депозита (RUB и TRC20) и вывода;
- восстановление production-like бэкапа с совпадением ledger;
- суточная сверка без расхождений;
- 72-часовой soak без необъяснённых финансовых событий.

## Что сознательно не делается

Собственный custody, вторая платёжная система, автоматический вывод без ручной
проверки крупных сумм — после подтверждения пилотной экономики, не до.
